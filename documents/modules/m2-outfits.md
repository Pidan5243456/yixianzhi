# M2 穿搭与试穿记录

状态：自配搭配保存、收藏、本地预览和缺失衣物处理已接入；AI 结果已实体化并通过同步恢复；真实供应商联调仍待配置。

## 三种不同的数据

| 对象 | 用途 | 是否需要 AI |
|---|---|---|
| 穿搭 `customOutfits` | 可复用的一组衣物 ID，带名称和场景 | 否 |
| 编辑草稿 `outfitDraft` | 当前工作区尚未保存的选择 | 否；当前仅本机 |
| 试穿记录 `history` | 一次生成或演示合成结果，关联当时的衣物和模特 | 真实试穿需要显式调用 |

穿搭字段：`id`（`o_` + UUID）、`name`、`scene`、`items`（1～4 个不重复 ID）、`createdAt`、`updatedAt`。收藏保存穿搭 ID，不以图片 URL 充当身份。

试穿记录当前包含 `id`、`outfitId`、`modelId`、`items`、`scene`、`time`、`image`、`kind`。`kind=collage` 是演示叠图，`tryon` 是生成结果；旧记录保留兼容显示。生成结果不是尺寸或合身保证。

## 交互规则

“保存搭配”“AI 推荐”“生成试穿”是三个独立操作。选衣、换模特、重开详情、收藏和返回仅更新本地预览。推荐只返回衣物组合，不连带试穿；用户决定是否保存。

生成前捕获不可变的模特、衣物及组合快照。生成期间继续编辑不得把返回图片标到新组合；同账号的旧结果仍应进入正确记录。切换账号后结果不得写入新账号。

删除穿搭同时清理它的收藏，但历史图片继续存在。删除衣物后，穿搭详情展示缺失并能进入编辑；全部衣物缺失也不能渲染成空白故障页。

## 结果协议

试穿记录 ID 为 h_ + operationId；先保存输出媒体与记录，再标记操作 done。App 关闭、网络超时、回执丢失时通过任务查询恢复，不自动创建付费重试。客户端不再重复创建远程结果；试穿记录页展示任务状态并提供主动重试。真实效果、演示拼贴与旧记录有可见标签。

验收：手动保存不依赖图片生成；收藏重开仍在；演示与真实结果区分；旧响应不覆盖新选择；结果恢复幂等；用户删除的结果不被后台再次恢复。
