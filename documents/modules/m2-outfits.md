# M2 穿搭与试穿记录

更新：2026-11-22，1.5.0。保存穿搭、规则选搭、拼图预览均不依赖模型。

## 日常与网购两条链路

日常：拍自己的衣物并标为“我已拥有” → 在搭配页选择日期（默认本地明天）、场景、可选手动温度 → 免费规则选一套或手动选衣 → 保存搭配 → 有需要时主动试穿。

规则仅用拥有的衣物。场景匹配和保暖标签参与排序，温度≤12°C偏向保暖，≥25°C偏向轻薄，其他偏向适中。缺件时给部分组合和缺少类别，不暗中补预设/想买衣物；标签缺失说明不确定，低温提醒另确认外套与实际保暖。当前四类不单列外套，不能把规则建议当成完整天气着装保障。

网购：商品图标为“想买” → 选择这件作为锚点 → 从已拥有衣物里配其他单品 → 保存“试搭 · 含未购买衣物” → 可选试穿 → 实际购买后在衣物预览点击移入衣橱。重新打开保存的试搭，规则和 AI 推荐仍优先使用想买锚点。

预设仅在用户明确选择预设锚点时参加该次示例推荐；手动抽屉保留预设并标明来源。新选择想买衣物会替换其他想买锚点。

## 三种数据

| 对象 | 数据 |
|---|---|
| customOutfits | id/name/scene/items/createdAt/updatedAt/context，items 为稳定衣物 ID |
| outfitDraft | 当前选择、outfitId 和 context；仅本机 |
| history | 冻结提交对应的结果图、关联 IDs、scene/context/time/kind |

context={date,scene,temperature}。date 是用户选择的 YYYY-MM-DD，不做时区换日；temperature 可为空，单位°C，范围-50～60，界面标明手动设置。当前不获取定位、天气或日历。

试搭状态根据当前引用衣物的 ownership 计算，购买后不再标未购买。删除衣物保留缺失引用；历史图保留。收藏使用穿搭 ID。保存时检查对象与引用仍有效，避免旧弹窗复活已删搭配。

## 生成与同步

“保存搭配”“选一套”“AI 推荐”“生成试穿”独立。进入页面、换衣、换模特不启动模型。拼图明确标为“搭配拼图”；本地模式保存结果标为演示拼贴，不冒充试穿。

生成捕获衣物、模特与条件快照。舞台用图片内容哈希判断输入是否变化：同图 data URL/media 引用转换不失效，改名或购买不失效，同 ID 换字节或模特图变化使旧结果失效；旧任务仍可在历史中恢复。切账号不能继续提交旧输入。

服务器保存图片、history h_<operationId>、变更日志和任务 done 在同一事务。任务超时不自动重试，用户在记录页查看并决定。真实试穿效果和合身判断尚未验收。
