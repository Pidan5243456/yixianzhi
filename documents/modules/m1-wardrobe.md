# M1 衣橱管理

状态：手动添加、编辑、删除和空衣橱流程已接入并在新仓库浏览器回归；AI 整理已接入统一任务，真实模型需配置后联调。

## 用户流程

新用户衣橱为空。选择相册或相机 → 在本机压缩图片 → 编辑名称、类别和场景 → 手动保存。进入页面和保存衣物不调用 AI。

衣橱默认展示自己的衣物；旧版示例在独立筛选项中保留，以兼容既有引用。灵感图片不能悄悄记为用户拥有。

## 衣物数据

| 字段 | 当前含义 |
|---|---|
| `id` | 手动衣物为 `c_` + UUID，编辑不更换 ID |
| `name` | 用户名称；页面最多 80 字符 |
| `cat` | 上衣、下装、鞋子、连体裙 |
| `scene` | 使用场景 |
| `dataUrl` | 页面录入压缩图；持久快照及同步实体使用 media 引用，Blob 单独缓存 |
| `source` | 手动来源为 `manual` |
| `createdAt` / `updatedAt` | 当前实现使用毫秒时间戳 |
| `sourceJob` | AI 生成单品可关联拆图任务 |

当前列表上限 1000。服务端已有类别等检查，但与页面的所有字段限制还需在 v2 契约中统一。

## 删除与引用

删除衣物只移除衣橱中的记录；自配搭配继续保留原衣物 ID，显示缺失并允许用户修改。已生成的试穿图保留。删除全部衣物后再次打开不能恢复默认示例。

AI 拆图产生的衣物使用稳定任务 ID 与目标序号去重。服务端稳定实体 ID 防止重复落库；服务端实体墓碑防止已删除结果通过任务恢复再次出现。

## 可选 AI 整理

在衣物预览中主动选择整理，确认后才提交原图。整理可能生成多件平铺单品，应保留原手动衣物；失败不影响它。成功图片需先可靠存储再标记完成。

浏览器验证覆盖手动编辑、空衣橱、缺失状态、远程模式浏览零 AI 提交及跨设备删除去重；后端覆盖磁盘失败、预算竞争、阶段复用。真机相册/相机仍待验证。
